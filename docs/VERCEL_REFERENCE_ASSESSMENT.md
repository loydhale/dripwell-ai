## Coding factory, development only

The [Software Factory template](https://vercel.com/templates/eve/eve-software-factory) uses separate classifier, analyst, implementer and reviewer stations. This fits the project's planning, Coder and independent Auditor split. Its [repository documentation](https://github.com/vercel-labs/eve-software-factory-template) says implementation runs in an isolated sandbox and pushes a branch before the reviewer evaluates it. Its normal workflow opens a new draft PR; local TUI GitHub changes require a human approval. It also handles factory-owned failed CI with at most two fixes. These defaults do not match the current requirement to publish only reviewed changes to the existing feat/dripwell-consultation-v2 branch and PR2.

Pinned source inspected: vercel-labs/eve-software-factory-template at [6bc5febab95de4c05fa08b164f544650f6aa11aa](https://github.com/vercel-labs/eve-software-factory-template/tree/6bc5febab95de4c05fa08b164f544650f6aa11aa). This is an API model route; it does not inherit Codex's Sign in with ChatGPT subscription access. Model, Sandbox, Blob and Connect availability, authorization and usage remain separate from the open-source template. No new provider choice or charge is made by this assessment.

The [package manifest](https://github.com/vercel-labs/eve-software-factory-template/blob/6bc5febab95de4c05fa08b164f544650f6aa11aa/package.json) targets Node24 and includes eve, AI SDK, GitHub tools, Vercel Connect and Blob, with different dependency ranges and TypeScript tooling from DripWell. Keep any factory tooling in a separate development workspace and use that workspace's version-matched docs. Do not copy its manifest over DripWell's lockfile or replace authored apps/web/agent or apps/web/workflows. The repository reports an MIT license.

Before enabling the full factory against DripWell, a bounded development adapter/preflight must enforce these existing requirements:

4. Reuse accepted checks until relevant source changes. Factory CI auto-fix cannot restart consumed recording scopes, retained-target work or TASK057's permanent release hold.
5. Establish an actually eligible selected model/runtime route without purchasing credits, pooling one subscription across users, silently swapping providers or assuming existing Gateway403 disappeared. Connector/App access and factory storage/sandbox setup require their own actual evidence.

These are a concrete adoption preflight, not an implemented adapter or a working continuous coding worker. The managed coding environment and Coder/Auditor workflow remain available. This assessment does not independently verify coding-account billing entitlement or full Foreman activation.

## Interface direction and next work

The recommended starting point remains the [two-screen GUI proposal](GUI_CONVERSION_PLAN.md): a board centered on active consultations and one visit with an obvious next action. Use Once UI as a styling/component candidate and the Linear-style tracker as a work-list/detail candidate. Use the admin/B2B examples for owner navigation and Liftoff for capture/review simplicity. A supplied reference is not an Owner-selected final layout; no screenshot/demo was inspected for visual matching in this assessment. Do not repeat the earlier optional design question.

A prototype should preserve all six board meanings/triggers, required questions, exact-revision approvals, actual care, separate commercial outcomes, wellness review, recording/unsaved-audio guards, archive/restore and reminders. Test tablet and empty/loading/blocked states. Presentation work can proceed independently of missing email/model access when its bounded task is selected; it cannot be used as pilot or release evidence or to reopen a held execution path.
